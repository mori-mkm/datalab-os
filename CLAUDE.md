# DataLab OS: instructions for Claude Code

## Git
Matheus owns every history-changing Git operation. Never run `git add`, `commit`, `push`, `merge`, `rebase`,
`reset`, create tags or PRs. Inspecting (`status`, `diff`, `log`, `branch`) is fine. When work is done, only
*suggest* a commit message.

## How work is organized
- **Development agents** (`.claude/agents/`) build this repo. **Runtime agents** (`src/datalab/agents/`) analyze
  datasets when DataLab runs. They are unrelated; never mix the two.
- Read `docs/agents/TEAM_ORCHESTRATION.md` before substantial work.
- **1 task = 1 owner = 1 bounded context.** Do not let one agent silently become the full-stack owner.
- Cross-cutting work (backend + frontend, a changed contract, a milestone) starts with the `architect`.
  A small single-area change goes straight to its one owner, or is done directly. Not every task needs every agent.
- Specialists: `langgraph-engineer` (backend), `control-plane-engineer` (`apps/control-plane`),
  `ds-methodologist` (only when analytical semantics change), `evaluator` (tries to break the change),
  `reviewer` (independent final verdict). The evaluator and reviewer never implement what they judge, and the
  reviewer never reuses the evaluator's conclusions without checking the diff.
- Pass agents a bounded handoff (`docs/agents/TASK_HANDOFF.md`), not the conversation history. An agent widens
  its reading only when evidence shows it must.

## Product invariants (short; details live in the README)
- LangGraph is the source of truth for the workflow. The Control Plane only observes; `/api/graph` is read back
  from the compiled graph, and topology is never re-declared in TypeScript.
- `DataLabState` stays small and JSON-like (no DataFrames or models). Node ids are stable machine ids
  (`department.agent`) and events are keyed by `node_id`.
- Analytical agents are deterministic; Ollama is used only in `head_ds` and `report`. Local-first, zero paid APIs.
- Demo mode never claims analytical results.
